# Track B — Sources & ARCH v1 (implementation slice, NOT full connector launch)

## Shipped in this branch

A visible **Sources & ARCH** page in the desktop workspace provides:

- Google Drive plain text, GitHub Markdown and Google Calendar event notes **manual pasted text** import.
- A hard 250 KiB UTF-8 limit, control-character validation, NFC/line-ending normalization, SHA-256 preview and explicit per-source selection **and** approval.
- Re-verification of source metadata/content SHA before persisting to an account-scoped local document.
- Import to shared Documents or the current Interview Kit, always **unselected** for AI retrieval by default. Users must deliberately enable a document through its normal selection controls.
- Source provenance ledger, duplicate detection for exact source/revision/content, removal of the document and associated professional evidence.
- Versioned ARCH Professional Evidence workspace with editable headline, role targets and goals. Quotes must be verbatim excerpts in an approved stored document, carry source and revision metadata, and are never silently generated by an LLM.
- Account-scoped persistence; Delete Account's existing scoped-storage purge covers both new stores.

## Explicitly NOT present

1. **No remotely connected accounts**: OAuth flows, Google/Composio/Activepieces SDKs, provider tokens, sync jobs and secure backend connector authorization are NOT implemented. The UI says this plainly; a pasted source/account label is not a verified login.
2. **No auto-sync**: preview/approval is initiated from the user-selected local text only. Source updates create new reviewed imports rather than mutating or unexpectedly exposing existing documents.
3. **No Live critical path changes**: ARCH professional quotes are not injected into Live, Solo, Career, user résumé or system prompts. Imported documents are initially unselected; only the existing explicit document-selection mechanism may allow subsequent RAG retrieval.
4. **No fabricated professional graph**: this is a versioned provenance ledger and user-editable profile, not the planned autonomous professional state graph, competency progression or cross-session learning.
5. **No Windows/device certification**: CI can check build, tests and smoke but not OAuth, real system audio, 90-minute Live sessions or UX on the user's device.

## Security decisions

- No secrets or raw provider tokens accepted in source-form fields.
- No provider/network/LLM calls during preview, import or evidence creation.
- No HTML injection: source content and quote rendering use JSX text content.
- No import without explicit selection and approval; no account-scope crossover between preview and write.
- The import ledger stores metadata and hashes; the underlying raw source lives in the existing account-scoped Documents store.
- The user's approval to import one source is not a broad OAuth grant.
- A source's manually entered account label **does not establish authenticated account ownership**; never repurpose it as a server access control.

## Next requirements before real OAuth connectors

Implement a trusted backend connection gateway with user-authenticated authorization, provider-specific minimum scopes, a consent diff and clear retention policy, PKCE/system-browser desktop callback, callback state/CSRF validation, server-side token custody and revocation, explicit account-profile switch and per-source allowlists, source freshness validation, rate limits, dedup/change policies, Windows packaged Connect Link testing, and data isolation tests. Keep the connector gateway out of Live's critical latency path.

The original offline Composio spike lives in `spikes/composio-compat/`; it is not proof of a live integration.
